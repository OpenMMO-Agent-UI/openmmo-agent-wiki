Every roll happens **on the server**. The client only sends "I want to attack
this monster"; the server decides what happened.

## Hit resolution

Attacks roll an **exploding d20**:

```
roll total + attack bonus >  target Guard   →  hit
roll total + attack bonus ≤  target Guard   →  miss
```

Note it's **strictly greater**. Rolling exactly the target's Guard is a
**miss**.

**Attack bonus**:

- Player = `floor(level / 2)` + your **STR modifier** + weapon enchant `+N`
- Monster = **level** (not halved) — steeper than the player curve, because
  player Guard climbs from gear rather than level. A CSV `attackBonus` in
  `monsters.csv` overrides the default, and dungeon depth scaling stacks on
  top of whichever value applies.

### Exploding d20

Roll a d20. **On a 20, roll again and add it.** If that roll is also 20, add
again (up to 5 extra rolls — a total of 120 already beats any Guard).

```
Roll 13          →  total 13
Roll 20, 10      →  total 30
Roll 20, 20, 4   →  total 44
```

**Why.** A flat "natural 20 always hits" rule floors hit chance at exactly
5% — an artifact of the die having 20 faces, not a balance choice: a kobold
would land a hit on a fully plate-armored player once every twenty swings no
matter how much Guard you stack. The exploding die instead **shrinks the odds
the further short you are, without ever flooring at zero**: every time the
gap crosses another 20 points, the chance is cut by another 1/20. A kobold
(+1) hits Guard 40 just 0.25% of the time — about once every 400 swings, or
13 minutes at its 1.9s attack cooldown. A natural 1 gets no special
treatment.

:::note[No critical-fumble rule — and no guaranteed miss either]
Unlike most D&D-derived systems, this one has **no natural-1-always-misses
rule.** If your `attack bonus ≥ target Guard`, even a 1 connects — hit chance
really does reach **100%**. In the other direction, hit chance **approaches
0% but never truly reaches it** — the exploding die always leaves a chance
(see above), even if it takes hundreds or thousands of swings.
:::

**Stacking Guard pays off very directly** — within the attacker's plain
d20 range, each +1 costs them 5% hit chance. Past that range the exploding
die takes over, and the odds drop much faster than 5% per point since each
extra 20-point band costs another 1/20. A full plate set (19 Guard total)
plus an armor enchant scroll makes you nearly unhittable by low-level
monsters, but deep-dungeon monsters keep pace better since their attack
bonus tracks their level directly.

## Damage

Damage is only rolled on a hit. Dice notation is `{count}d{sides}`:

```
2d6  →  roll two six-sided dice and sum (2–12)
```

Player melee adds your **STR modifier**.

  placeholder="Search weapons…"
  columns={[

The STR modifier applies **to every hit**, so it lifts low-damage weapons
proportionally more: STR 18 (+4) with a Dagger (1d4, average 2.5) actually
averages 6.5 — 2.6× the base.

## The Guard scale

Guard is NetHack's AC inverted — **higher is better.**

| Guard | Meaning |
|---|---|
| 0–7 | Barely defended |
| 8–9 | Light defence |
| 10 | Ordinary |
| 11–13 | Solid |
| 14+ | Heavy armor and up |

Against NetHack: `Guard = 10 − AC`.

## Experience

### XP per kill

```
XP = 1 + level² + max(Guard - 10, 0) × 2
```

Guard above 10 earns a bonus — **harder monsters pay more.**

  placeholder="Search monsters…"
  columns={[

    { key: 'level', label: 'Level', align: 'right' },
    { key: 'guard', label: 'Guard', align: 'right' },
    { key: 'xp', label: 'XP', align: 'right' },
    { key: 'hp', label: 'Health', align: 'right' },
    { key: 'perHp', label: 'XP / health', align: 'right' },

  rows={monsters.slice()
    .sort((a, b) => monsterXp(a.level, a.guard) - monsterXp(b.level, b.guard))
    .map((m) => ({
      name: m.name, level: m.level, guard: m.guard,
      xp: monsterXp(m.level, m.guard), hp: m.healthEffective,
      perHp: (monsterXp(m.level, m.guard) / m.healthEffective).toFixed(2),
    }))}
/>

**XP / health** is the efficiency column — higher means more XP per point of
health you have to chew through. The Orc Warlord gives the most XP but takes
120 health to get there, so it isn't the most efficient.

### XP to level

```
XP(n) = 20 × 2^(n-2)      (n ≥ 2)
```

**Every level costs exactly twice the last** — a pure exponential with no
easing.

<FilterTable
  placeholder="Enter a level…"
  columns={[
    { key: 'level', label: 'Level', align: 'right' },
    { key: 'total', label: 'Cumulative XP', align: 'right' },
    { key: 'band', label: 'This level costs', align: 'right' },
    { key: 'orcs', label: 'Orcs, roughly', align: 'right' },
  ]}
  rows={Array.from({ length: 20 }, (_, n) => n + 1).map((level) => {
    const orcXp = monsterXp(4, 11);
    const band = level === 1 ? 0 : xpForLevel(level) - xpForLevel(level - 1);
    return {
      level,
      total: xpForLevel(level).toLocaleString(),
      band: level === 1 ? '—' : band.toLocaleString(),
      orcs: level === 1 ? '—' : Math.ceil(band / orcXp).toLocaleString(),
    };
  })}
/>

The last column converts to Orcs (level 4, Guard 11,
{monsterXp(4, 11)} XP each). Past the first ten levels, grinding on the current
monster roster gets very slow — the game's content today lines up with roughly
the first ten levels.

## The death penalty

Dying **costs no equipment** but does cost XP:

```
level band = XP(L+1) - XP(L)
penalty    = max(1, floor(band × 0.15))
```

That's **15% of your progress through the current level.**

### Losing a level

If the deduction drops you below the level's starting XP you **lose a level.**
Two protections:

- **At most one level per death.**
- **Level 1 never drops.**

After a drop your XP is floored at **30% through** the lower band, so you don't
end up stuck just short of relevelling over and over.

<FilterTable
  placeholder="Enter a level…"
  columns={[
    { key: 'level', label: 'Level', align: 'right' },
    { key: 'band', label: 'Level band', align: 'right' },
    { key: 'penalty', label: 'Lost on death', align: 'right' },
    { key: 'orcs', label: 'Orcs to recover', align: 'right' },
  ]}
  rows={Array.from({ length: 12 }, (_, n) => n + 2).map((level) => {
    const band = xpForLevel(level + 1) - xpForLevel(level);
    const penalty = Math.max(1, Math.floor(band * 0.15));
    return {
      level, band: band.toLocaleString(), penalty: penalty.toLocaleString(),
      orcs: Math.ceil(penalty / monsterXp(4, 11)).toLocaleString(),
    };
  })}
/>

### Losing a level costs health too

So that repeatedly levelling up and down can't be farmed for health, **the
distribution of health lost on a level-down is identical to the health gained
on a level-up**:

```
roll the hit die, guarantee at least half, add the CON modifier
```

The long-run expectation is therefore **zero** — no statistical gain from
cycling. Health also never drops below your level 1 value.

## Respawning

Request a respawn and the server confirms your health is 0, refills it and
returns you to the origin `(0, 0, 0)`. Satiation resets to 300 — the bottom of
the Well-Fed band — so you don't respawn starving and immediately go Weak.

## Monster AI

Monster AI runs on the client, but **attack resolution always goes to the
server.**

| State | Meaning |
|---|---|
| `idle` | Waiting (30% chance to wander) |
| `walk` | Moving |
| `run` | Chasing a player (within chase range) |
| `attack` | Attacking (within attack range) |
| `hit` | Stagger from being hit (~800 ms) |
| `dead` | Dead |

A dead monster is removed after **30 seconds**. Per-monster chase ranges and
attack intervals are in [Monster index](../../database/monsters/).
