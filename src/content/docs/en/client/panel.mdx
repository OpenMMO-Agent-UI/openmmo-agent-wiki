This page takes the client panel apart feature by feature. If you just want to
get playing, [Install and first run](../install/) is enough.

## The header

| Element | What it does |
|---|---|
| Connection status | Whether you're connected |
| Vitals | Your character's live numbers |
| Spectator memory use | How much memory the 3D view is holding |
| Reload | Reloads the 3D spectator view (use it if the view freezes or corrupts) |
| **Pause / Resume (⏸ / ▶)** | Pauses a running agent. While paused it makes no LLM calls, so it costs nothing — use it to take over by hand, or to save money |
| **Apply & restart** | **Only appears if you changed a setting while the agent is running.** The agent reads its config once at startup, so this is how a change takes effect |
| Manual / AI switch | Swap between the two modes live |
| Change character / server | Back to the earlier screens |

## The three drawers

The icons down the left edge carry no text; the labels appear on hover and
focus rather than waiting on an OS tooltip.

### Character

Three tabs:

- **Stats** — level, attributes, learned skills and titles. Titles are switched here.
- **Equipment** — every worn slot, empty ones included.
- **Bag** — what is carried, and the sell/drop marks (next section).

:::note[Why equipment comes from the relay]
The agent's own panel API **reports the bag and never the worn gear**.
So the Equipment tab is reconstructed from the inventory frames the relay
sees — one of the things the desktop client adds, and not visible if you run
`agent-client` directly.
:::

#### The bag's sell and drop marks

Every row carries two checkboxes, with the columns named once above the list
rather than restated per row:

- **Sell** — the worker may sell it to a merchant
- **Drop** — the worker may leave it on the ground

Ticking only stages the change; **Apply labels** is what writes it. A few
things worth knowing:

- A mark is **per item**, not per enchant level — the agent's own sell and
  drop actions carry no enchant field. So one item's enchant variants group
  into a single row, with the levels named in the label (`Iron Sword (+0, +2)`).
- The **Show every item in the game** toggle above the list swaps it for every
  carriable item the game ships, so **you can mark something before you own
  it** — which is the point for a dungeon conqueror: the thing you want to
  decide about in advance is exactly the thing you have not picked up yet.
  The default lists only what is in the bag.
- **Unmarked means untouched.** This is the gate that stops a worker selling
  the gear you earned.
- Two kinds ignore a mark: the **kit it lives on** (potions, return scrolls,
  food, a fishing rod, reins) and **dungeon keys**. Dropping a key puts a
  dungeon run in a loop — bin it, re-farm it, bin that one too.
- Marked both ways is **sold, not dropped**: selling pays.
- The drop mark applies **before the pickup** — a marked item is not picked up
  at all, so its weight is never carried. Anything already in the bag
  underground is shed on arriving at each new floor.

and a **cap** (up to three digits):

    { field: 'Potions', default: '10', note: 'Healing potions' },
    { field: 'Scrolls', default: '5', note: 'Return scrolls. The last one is never spent commuting — that is the low-health escape' },
  ]}
/>

Restocking has a few rules that are not written on any field:

- Order something this merchant does not stock and it falls back to whatever
  else of that category is on the shelf — bread is Wick's, not Rica's.
- **Merchants sleep.** At night a shopkeeper walks home and gets into bed, and
  the server refuses every trade with one who has. A worker does not count a
  sleeping shopkeeper as the merchant it came for: it walks the town's stops
  looking for one who is awake, and if none is, waits five minutes and comes
  back — saying in the log which shopkeeper is asleep.
- The dungeon conqueror **will not go in without potions**: it waits by the
  door until a shop can sell some. Unless the purse cannot cover one, in which
  case it dives anyway — its gold comes from the chest, so waiting there would
  be a deadlock rather than patience.

### Activity

Two tabs:

- **Thoughts** — the worker's decision and progress line each turn, timestamped,
  with a **filter**, **Follow** (stick to the newest) and **Clear**. The dungeon
  conqueror says which floor it is on, which key it owes, and why it stopped.
- **Log** — the agent process's own stdout / stderr.

Thoughts for why it decided something; Log for why it broke. **Drops are named
here too**, item by item — a dropped item does not come back, so this is the
only account of what went.

:::note[The translation LLM has nothing to do with who plays]
What plays the character in Auto mode is the **rule engines** above, and they
call no LLM. These settings only translate chat; automatic play works fine
without them.
:::

### About

Version, check for updates, clear the asset cache, the privacy note (app starts
and play modes only, via Aptabase — **never your account, characters or
servers**), and an **Advanced** block holding **Watch port** (the local
spectator panel's port, default 8808) and **Log level** (turn on debug before
reporting a problem).

## Connection profiles

Managed on the **Server** screen. The built-in `openmmo.to.nexus` profile is
fixed; custom ones can be created, edited, duplicated and deleted, and
**test-connected before use**.

A profile holds:

| Field | What it is |
|---|---|
| Profile name | Name of the profile |
| Game server | The server's WebSocket address |
| Terrain origin | Where terrain assets are fetched from |
| Google client ID | The OAuth client that server accepts |
| Google client secret | Its secret, stored encrypted |

**These five travel as a set** — a server only accepts sign-in tokens issued by
a client ID on its own allowlist, so client IDs can't be shared between
servers.

## Where your secrets live

API keys and connection-profile secrets are encrypted with the OS keychain
(Electron `safeStorage`, with an AES-GCM fallback) and handed to the agent as
**environment variables**.

**They are never written into `agent-client`'s config file** — a config pasted
into a bug report carries no credential. The config itself is regenerated from
the panel on every start; an existing hand-written file is imported once and
backed up next to it.
