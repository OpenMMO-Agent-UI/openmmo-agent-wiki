이 페이지는 클라이언트 패널의 기능을 하나씩 풀어 설명합니다.
빠르게 시작하는 것만 원한다면 [설치와 첫 실행](../install/)으로 충분합니다.

## 헤더

| 요소 | 역할 |
|---|---|
| 접속 상태 | 서버에 붙어 있는지 |
| 체력과 상태 | 캐릭터의 실시간 수치 |
| 관전 메모리 사용량 | 3D 관전 화면이 쓰는 메모리 |
| 새로고침 | 3D 관전 화면 다시 불러오기(멈추거나 깨졌을 때) |
| **일시정지 / 재개(⏸ / ▶)** | 실행 중인 에이전트를 멈춤. 멈춰 있는 동안 LLM을 호출하지 않으므로 비용도 발생하지 않음 — 잠깐 직접 조종하거나 비용을 아낄 때 |
| **Apply & restart** | **에이전트 실행 중에 설정을 바꿨을 때만 나타남.** 에이전트는 시작할 때 설정을 한 번만 읽으므로 반드시 눌러야 반영됨 |
| **자동 / 수동 전환** | 두 모드를 즉시 전환. 자동 모드에서 캐릭터를 실제로 움직이는 것은 **자동 워커**(아래) |
| 캐릭터 변경 / 서버 변경 | 앞 화면으로 되돌아감 |

## 왼쪽 서랍 세 개

왼쪽 가장자리의 아이콘에는 글자가 없습니다. 마우스를 올리거나 키보드로
포커스를 주면 이름이 나타납니다.

### 캐릭터(Character)

탭 세 개:

- **능력(Stats)** — 레벨, 능력치, 배운 기술, 칭호. 칭호는 여기서 바꿉니다.
- **장비(Equipment)** — 착용 중인 모든 슬롯. 빈 슬롯도 함께 표시됩니다.
- **가방(Bag)** — 들고 있는 물건과 판매/버리기 표시(다음 절).

:::note[장비는 왜 중계를 통해 보나]
에이전트 자신의 패널 API는 **가방만 알려주고 착용 장비는 알려주지 않습니다.**
그래서 장비 탭은 중계가 본 인벤토리 프레임에서 복원한 것입니다 —
데스크톱 클라이언트가 더해주는 것 중 하나이며, `agent-client`를 직접
실행하면 볼 수 없습니다.
:::

#### 가방의 판매·버리기 표시

각 줄에 체크박스가 두 개 있고, 열 이름은 목록 위에 한 번만 적혀 있습니다:

- **판매(Sell)** — 워커가 상인에게 팔아도 됨
- **버리기(Drop)** — 워커가 땅에 버려도 됨

체크는 임시 저장일 뿐이고, **Apply labels**를 눌러야 기록됩니다. 알아둘 점:

- 표시는 **아이템 단위**이며 강화 수치는 구분하지 않습니다 — 에이전트의
  판매·버리기 행동에 강화 항목이 없기 때문입니다. 그래서 같은 물건의 강화
  단계들은 한 줄로 묶이고, 수치는 이름에 적힙니다(`철검 (+0, +2)`).
- 목록 위의 **게임의 모든 아이템 표시** 전환은 게임이 제공하는 들 수 있는
  모든 아이템으로 목록을 바꿉니다. 그래서 **가지고 있지 않아도 미리 표시할 수
  있습니다** — 던전 정복자에게는 이것이 핵심입니다. 미리 정해두고 싶은 물건은
  바로 아직 줍지 않은 그 물건이니까요. 기본값은 가방에 있는 것만 보여줍니다.
- **표시하지 않으면 손대지 않습니다.** 어렵게 얻은 장비를 워커가 팔아버리지
  않게 막는 관문입니다.
- 표시를 무시하는 두 종류가 있습니다: **살아가는 데 쓰는 보급품**(물약, 귀환
  주문서, 음식, 낚싯대, 고삐)과 **던전 열쇠**. 열쇠를 버리면 던전 공략이
  무한 반복에 빠집니다 — 버리고, 다시 파밍하고, 또 버립니다.
- 양쪽 모두 표시하면 **버리지 않고 팝니다**: 파는 쪽이 돈이 됩니다.
- 버리기 표시는 **줍기 전에** 적용됩니다 — 표시한 물건은 아예 줍지 않으므로
  무게도 지지 않습니다. 던전 안에서 이미 가방에 있는 것은 새 층에 도착할 때
  버립니다.

  ]}

보급에는 어느 항목에도 적혀 있지 않은 규칙이 몇 가지 있습니다:

- 그 상인이 팔지 않는 물건을 지정하면 같은 종류의 다른 물건으로 대체합니다 —
  빵은 Rica가 아니라 Wick의 것입니다.
- **상인은 잠을 잡니다.** 밤이 되면 상점 주인은 집으로 걸어가 침대에 눕고,
  서버는 잠든 상대와의 모든 거래를 거부합니다. 워커는 잠든 주인을 "찾아온 그
  상인"으로 취급하지 않습니다. 마을의 지점들을 돌며 깨어 있는 상인을 찾고,
  아무도 없으면 5분 뒤에 다시 와서 누가 자고 있는지 기록에 남깁니다.
- 던전 정복자는 **물약 없이는 들어가지 않습니다**: 상점이 팔 수 있을 때까지
  문 앞에서 기다립니다. 단, 지갑이 한 병도 감당하지 못하면 그냥 내려갑니다 —
  던전 정복자의 돈은 상자에서 나오므로, 그 상황에서 기다리는 것은 인내가
  아니라 교착 상태입니다.

### 활동(Activity)

탭 두 개:

- **Thoughts** — 워커가 매 턴 내린 결정과 진행 설명. 시간이 함께 기록되고
  **필터**, **Follow**(최신으로 따라가기), **Clear**가 있습니다. 던전 정복자는
  몇 층인지, 어느 열쇠가 없는지, 왜 멈췄는지를 여기서 말합니다.
- **Log** — 에이전트 프로세스 자신의 stdout / stderr.

왜 그렇게 결정했는지는 Thoughts, 왜 고장났는지는 Log를 봅니다. **버린 것도
여기에 하나씩 적힙니다** — 버린 물건은 돌아오지 않으므로, 무엇이 사라졌는지
확인할 수 있는 유일한 기록입니다.

### About — 정보

버전, 업데이트 확인, 리소스 캐시 지우기, 개인정보 안내(Aptabase를 통해 앱
시작과 플레이 모드만 보고하며 **계정·캐릭터·서버는 절대 포함하지 않습니다**),
그리고 **Advanced** 블록의 **Watch port**(로컬 관전 패널 포트, 기본 8808)와
**Log level**(문제를 보고하기 전에 debug로 올리세요).

## 접속 프로필

**Server** 화면에서 관리합니다. 기본 제공되는 `openmmo.to.nexus`는 고정이라
수정할 수 없고, 직접 만든 것은 추가·편집·복제·삭제할 수 있으며
**쓰기 전에 연결 테스트**를 할 수 있습니다.

프로필 하나에 들어가는 것:

| 항목 | 설명 |
|---|---|
| Profile name | 프로필 이름 |
| Game server | 게임 서버의 WebSocket 주소 |
| Terrain origin | 지형 리소스 출처 주소 |
| Google client ID | 그 서버가 받아들이는 OAuth client |
| Google client secret | 대응하는 비밀값, 암호화 저장 |

**이 다섯은 한 세트여야 합니다** — 서버마다 자기 허용 목록에 있는 client ID로
발급된 로그인 토큰만 받으므로, client ID를 서버 간에 돌려 쓸 수 없습니다.

## 비밀값은 어디에 저장되나

API 키와 접속 프로필의 비밀값은 운영체제 키체인으로 암호화되고
(Electron `safeStorage`, 실패 시 AES-GCM으로 대체), **환경 변수**로 에이전트에
전달됩니다.

**`agent-client`의 설정 파일에는 기록되지 않습니다** — 그래서 설정 파일을 버그
리포트에 붙여넣어도 자격 증명이 새지 않습니다. 설정 파일 자체는 실행할 때마다
패널에서 다시 생성됩니다. 직접 작성해둔 파일이 있었다면 한 번 가져오고 옆에
백업을 남깁니다.
