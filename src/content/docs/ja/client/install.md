## 初回の開き方

### macOS —— そのまま開く

**macOS ビルドは Apple Developer ID で署名され、Apple の公証を受け、チケットがアプリに添付されています。** 展開してダブルクリックすれば、Gatekeeper の警告なしに起動します。

右クリック → 開く は不要で、`xattr -cr` も不要です —— 未署名アプリ向けにネット上で見つかる助言は、このビルドには当てはまりません。

### Windows —— クリックが一つ増える

**Windows ビルドは未署名**なので、SmartScreen が「Windows によって PC が保護されました」と表示します。**詳細情報** → **実行** を押してください。

コード署名証明書は毎年費用がかかり、現在あるのは macOS 用の一つだけです。このプロジェクトが役に立っているなら、[支援](https://ko-fi.com/dakywang)が Windows 証明書を現実的なものにします。

### Linux —— 実行ビットを立てる

AppImage に署名と呼べるものはありません。実行可能であればよいだけです:

```bash
chmod +x openmmo-agent-*linux-x64.AppImage
./openmmo-agent-*linux-x64.AppImage
```

## 初回起動

四つの画面を順に進めばゲームの中です。**別途「プレイ」の手順はありません** —— キャラクターを選んだ時点で入場します。

### 1. サーバー —— 接続プロファイルを選ぶ

内蔵の `openmmo.to.nexus` プロファイルは固定で、ほとんどのプレイヤーが求めるのはこれです。

プロファイルは三つをひとまとめにします:サーバー URL、地形アセットの配信元、そして Google のクライアント ID とシークレット。これらは組で動く必要があります。サーバーは自身の許可リストにあるクライアント ID が発行したサインイントークンしか受け付けないからです。自前のサーバーを運用しているなら、プロファイルの作成・編集・複製・削除ができ、使う前に接続テストもできます。

### 2. ログイン —— Google のデバイスフロー

ボタンを押すとコードが表示されるので、ブラウザで入力します。キャッシュ済みの認証情報があれば次の手順まで一気に進みます。

### 3. キャラクター —— 選ぶか作る

タブは二つ:

- **キャラクターを選ぶ** —— 1 アカウントにつき最大 3 体(サーバー側で制限)。クリックで入場、または削除。
- **新しいキャラクターを作る** —— 名前、職業、性別。上限に達すると非表示になります。

### 4. ゲーム

モードは入場時に自動で決まります:**LLM バックエンドが設定済みで検証を通れば自動、そうでなければ手動**。自動の起動に失敗した場合は手動に落ちます。ヘッダーからいつでも切り替えられます。

## 二つのプレイモード

サーバーは 1 キャラクターにつき操作セッションを厳密に一つしか許さないので、二つのモードはそこへの到達方法が異なります。

**手動プレイ**は直接接続です —— 組み込みの OpenMMO ウェブクライアントがあなた自身の Google アカウントでサインインし、サーバーと直接やり取りします。ブラウザで遊ぶのとまったく同じで、リレーも `agent-client` もありません。

**自動プレイ**は `agent-client` を起動し、それがその唯一のセッションを自分のために必要とします —— つまり「見る」ことは、その隣にログインすることでは実現できません。代わりにループバック上にリレーが入ります:

```
agent-client <--ws--> proxy (127.0.0.1) <--wss--> openmmo.to.nexus
                        |
                        +--> 観戦者 (/mirror)
```

サーバーはエージェントの背後に何かがあることを一切知りません。中間にいることで、リレーはサーバーからのすべてのメッセージを読み取り専用の観戦ビューへ複製できます。**リレーは `127.0.0.1` のみを待ち受けるので、何も端末の外へ出ません。**

## ゲーム画面

ヘッダーには接続状態、バイタル、観戦ビューのメモリ使用量、3D ビューの再読み込みボタン、手動 / AI の切り替え、キャラクターやサーバーを変更するボタンが並びます。エージェント稼働中に設定を変えると、**適用して再起動** ボタンが現れます。

左のレールは六つのドロワーを開きます:

| ドロワー | 表示される内容 |
|---|---|
| 装備 | 身につけているもの、装備欄ごとに |
| バッグ | 持っているもの、およびエージェントが売却・破棄してよい品 |
| 性格と記憶 | このキャラクター専用のプロンプト(編集可)と、エージェントが書き留めた内容(読み取り専用) |
| 座標 | 地点のブックマーク。「現在位置を使う」も含む |
| 指示プリセット | よく使う指示をワンクリックのボタンとして保存 |
| アクティビティ | タブは二つ:思考(すべてのプロンプトと応答)とログ(エージェントプロセスの出力) |

各ドロワーの詳細は[パネル機能詳細](../panel/)にあります。

ゲームビューの下に固定された**指示**は、稼働中のエージェントに届く唯一の操作です。指示を打ち込むとキャラクターの次のターンとして届きます。**ベストエフォートで、従われる保証はありません。**

## 鍵の保管場所

API キーと接続プロファイルのシークレットは OS のキーチェーン(Electron の `safeStorage`、代替として AES-GCM)で暗号化され、環境変数としてエージェントへ渡されます —— **`config.toml` には決して書き込まれません。** バグ報告に貼った設定ファイルに認証情報は含まれません。

## トラブルシューティング

**プロトコルバージョンの不一致** —— サーバーが更新されています。[ダウンロードページ](../download/)から新しいビルドを取得してください。

**設定を変えたのに何も起きない** —— エージェントは起動時に一度だけ設定を読みます。ヘッダーの **適用して再起動** を押してください。

**VS Code のターミナルから起動したが開かない** —— VS Code 自体が Electron アプリで、`ELECTRON_RUN_AS_NODE=1` が漏れるため、クライアントが素の Node として起動してしまいます:

```bash
env -u ELECTRON_RUN_AS_NODE npm start
```

**観戦ビューで何かが欠けている、または止まっている** —— 自動プレイの観戦ビューはスナップショットから始まるので、エージェントが知っていても現在追跡していないものは、視界に戻ってきた順に現れます。
